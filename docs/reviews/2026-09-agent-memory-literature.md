# Agent memory literature brief — 2026-09-29

Companion to [`2026-09-state-review.md`](2026-09-state-review.md) §6. A web
literature pass (2025–2026 weighted) over agent-memory systems, consolidation
and reflection, human-facing PKM with agents, multi-agent knowledge sharing
and evaluation, read against Lithos's architecture: Markdown notes as the
source of truth, hybrid Tantivy + Chroma search, a NetworkX wiki-link graph,
SQLite task coordination, and the LCMA layer (salience, coactivation, NER,
typed edges partly LLM-inferred, scouts + rerank, receipts).

Every claim is URL-backed. Vendor-reported numbers are flagged; section (d)
explains why none of them should be design targets.

## (b) The most transferable ideas for Lithos

1. **Bi-temporal validity and deterministic supersession on claims and typed edges.** Sources: Zep (2501.13956), MemStrata (2606.26511), STALE (2605.06527), Missing Knowledge Layer (2604.11364). In Lithos: add `valid_from`, `valid_to`, `recorded_at`, `superseded_by` to LCMA typed edges and to a lightweight `claims:` frontmatter list; when an LLM-inferred `contradicts` edge or a same-(subject, relation) claim with a new object appears, retire the old one deterministically (no LLM), keep it retrievable via `as_of=`; `lithos_retrieve` filters superseded claims by default and returns them under a `superseded` key. Value: this is the failure class everything else (Mem0, plain RAG) gets wrong 15–40% of the time, and it is exactly what a long-lived single-owner KB accumulates. Effort: M.
2. **Knowledge vs memory persistence semantics: stop decaying facts.** Sources: Missing Knowledge Layer, Selective Forgetting (2608.28978), MemoryBank. In Lithos: route salience decay by note kind: episodic material (findings, session notes, coactivation edges, receipts) decays and reinforces; declarative notes and claims never decay, they are only superseded; procedures need evidence-gated revision. Pruning ~10% of the low-signal episodic graph is free. Effort: S (policy table over existing salience code).
3. **Compile, don't (only) retrieve: LLM-maintained concept and entity pages as real notes.** Sources: Karpathy wiki, ProGraph profiles (2607.19359), TriMem (2605.19952), Infini Memory (2606.10677), Hindsight mental models. In Lithos: make the planned concept-node layer a set of `note_type: concept` / `entity` Markdown pages (Obsidian-visible) that a consolidation job rewrites from the atomic facts + NER entities + edges, with "compression residuals" (dates, numbers, ids) kept verbatim. Keep three granularities: raw notes (truth) → facts/edges (index) → synthesized pages (reasoning). Cross-entity traversal falls out of wiki-links in the prose. Value: highest of the list for the owner ("what do I know about X" becomes a page, not a search). Effort: L.
4. **Sleep-time consolidation as a scheduled Lithos task.** Sources: Letta sleep-time (2504.13171), Generative Agents reflection threshold, RMM prospective reflection. In Lithos: a recurring `consolidate` task any idle agent can claim; trigger a reflection pass when summed salience of un-reflected notes crosses a threshold; output insight notes with `derived_from` edges and updated concept pages. Pays off when queries are predictable, which they are for a single owner's recurring projects. Effort: M.
5. **Lint as a first-class, owner-visible workflow.** Sources: Karpathy lint, obsidian-wiki `/wiki-lint`, Memory-as-Metabolism AUDIT, claude-memory-compiler `check_contradiction`/`doctor`. In Lithos: a `lithos_lint` producing an "Open questions" note: contradictions, orphans (graph degree 0), stale claims, concepts mentioned by N notes with no page, and gaps phrased as questions an agent can pick up as tasks. Effort: S–M; most signals already exist.
6. **Close the loop on retrieval receipts: learn the reranker, reconsolidate on read.** Sources: RMM retrospective reflection (2503.08026), REALM (2609.16053). In Lithos: receipts already record what scouts returned; add "what was actually used" (agents report `used_ids`), train a tiny reranker over scout features; on each retrieval strengthen coactivation among co-used notes. Effort: M; the cheapest measurable win because instrumentation exists.
7. **Proactive, selective priming instead of always-on context.** Sources: Remember When It Matters (2607.08716), Claude Code MEMORY.md budget, Agent Skills progressive disclosure. In Lithos: the planned `lithos_task_prime` should be a gate: on task claim or session start compute a short brief (relevant claims, open contradictions, procedures) and inject only above a relevance threshold; otherwise a one-line index. Effort: M.
8. **Provenance, citation lock and abstention.** Sources: Agent Zero (2608.29606), Eywa (2605.30771), belief-reliability (2606.22030). In Lithos: every inferred edge/claim carries `evidence: [note_id#span]` and a source channel (owner-written > agent-observed > LLM-inferred); `lithos_retrieve` returns evidence pointers; the skill teaches agents to cite only ids they opened; reliability caps so many agent-inferred claims cannot outvote one owner-written note. Effort: M.
9. **Owner resurfacing: half-life digest, not a feed.** Sources: Readwise recall half-life, obsidian-wiki `/wiki-digest`, Memory-as-Metabolism, Mem 2.0. In Lithos: reinterpret salience as p(recall); a daily digest note with (i) what agents changed, (ii) superseded claims, (iii) 3–5 notes whose recall probability fell below 0.5 that connect to active projects, (iv) open questions from lint. Effort: S–M.
10. **Procedural memory as verified skills.** Sources: Agent Skills spec, Voyager, Skill-Pro verification gate (2602.01869), Claude Code auto-memory types. In Lithos: `note_type: procedure` notes with SKILL.md-compatible frontmatter, a promotion gate (≥1 successful task completion referencing it before `verified`), usage counts from receipts, and an export into `.claude/skills/`. Effort: M.
11. **Exploration via MMR + Thompson sampling over salience uncertainty.** Sources: U-Mem (2602.22406), diversity-aware retrieval survey (https://arxiv.org/html/2603.07670v1). In Lithos: implement "temperature" as (a) MMR diversification across scouts and (b) a Beta posterior per node (successes = used after retrieval, trials = retrieved); flag `explore=true` in receipts so serendipity can be measured. Effort: S.
12. **Multi-agent claim merging with preserved conflicts.** Sources: MELD (2608.16357), TRACE. In Lithos: findings go through insert/merge/relate/conflict/reject classification; conflicts are never auto-resolved but land in the `lithos_conflict_resolve` queue for the owner. Effort: M.

## (c) Ideas not worth copying

- **Full Microsoft-GraphRAG pipeline** (Leiden communities + community summaries over the whole vault). GraphRAG-Bench (2506.05690) and RAGSearch (2604.09666) show it often underperforms vanilla or agentic RAG and only pays off on multi-hop/global questions. Concept pages give the sensemaking benefit at a fraction of the cost.
- **Entity-triple decomposition as the primary store.** Selective Forgetting (2608.28978) measured a 30-point judged-correctness drop vs a flat store because surface form is lost; ProGraph/TriMem/Infini all move back to prose. Keep Markdown notes as truth; triples are an index only. Mem0 itself removed its queryable graph in 2026.
- **RL-trained memory managers** (Memory-R1). Single owner = no training distribution; MERIT shows the bottleneck is acting on retrieved facts (55%), not the ADD/UPDATE policy.
- **MemOS-style activation/parameter memory and MemoryOS-style OS tiers.** Irrelevant for a local MCP server fronting a Markdown vault; the tiers re-invent salience.
- **Ebbinghaus decay on everything.** Category error per 2604.11364; facts should be superseded, not forgotten. (Lithos's July salience collapse was this error in practice.)
- **Full-history replay / betting on 10M-token context.** "Never economical" (MERIT); rankings flip under retrieval budgets (2607.16848).
- **Vendor LoCoMo/LongMemEval scores as targets.** 6.4% wrong answer key, judges accept 63% of wrong answers, vendors tune themselves and run others on defaults.
- **The official MCP memory server's schema.** No provenance, ranking, validity or decay; Lithos is already past it.

## (d) Evaluation approach for Lithos's memory layer

1. **Ground-truth-first synthetic owner** (2607.21962, AMemGym): script a synthetic owner with facts that carry validity intervals, volatility classes and source channels; render notes, findings and sessions from the script; instantiate questions mechanically (recall, temporal, knowledge-update, abstention, implicit invalidation). Gold answers are correct by construction. Run at 3-week and 9-week simulated tenure to catch the tenure crossover.
2. **Task-outcome A/B on real agent work** (DolphinBench/MERIT/MemGym): a set of Lithos-repo tasks validated as *success with history, failure without*; run agents with memory off / search-only / full LCMA; report accuracy, tokens per query and latency together, and the "acted-on-retrieved-fact" rate.
3. **Receipt-driven offline eval.** Receipts already log scouts and results; add `used_ids` and replay receipts offline to compare scout/reranker/temperature configurations (nDCG on used items, exploration-use rate) without re-running agents.
4. **Judge hygiene.** Adversarially test any LLM judge with wrong-but-topical answers; use a stronger judge than the answerer; 5–10 seeds; treat differences under ~10 points as noise; keep prompts in-repo.
5. **Owner-facing metrics.** Digest open/act rate, contradictions resolved per week, lint questions converted to tasks, and time-to-answer for "what do I know about X" with vs without concept pages.
6. **Standing baselines.** Always include a full-context baseline and a plain filesystem/grep baseline (Letta's 74.0 LoCoMo with just files is the bar) so improvements are attributable to LCMA, not the model.
